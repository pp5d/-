## 🔀 关键决策与偏离

1. **全量同步（非增量）**：知识量小（几百条），全量同步几秒完成，比增量简单可靠。公网 import 清空重建 publish_to_public 知识。
2. **向量用 JSON 列（无需 pgvector）**：docker-compose 用官方 `postgres:16` 镜像，无需 pgvector 扩展（M3 已修订设计）。
3. **附件 base64 传输**：快照内附件以 base64 内嵌（图片/PDF 通常几 MB，视频附件少，可接受）。
4. **author_id 改为系统账号**：公网 import 时查找/创建 `sync_bot` 账号作为同步知识的作者，避免外键失败（修复了硬编码 author_id=1 的问题）。
5. **限流为单进程内存实现**：滑动窗口日志（deque 存时间戳），多 worker/多实例需换 Redis（公网单实例够用）。

## 📋 遗留项（部署时注意 / M6 处理）

1. **Docker 实际构建未验证**：沙箱无法 docker build，需在部署环境（IT 部门服务器）实测 `docker compose up -d`。
2. **默认密码/密钥**：compose 里 `SECRET_KEY=change-me`、`POSTGRES_PASSWORD=aiqa_prod_password` 生产必须替换。
3. **同步触发入口**：目前 push 靠 API 调用（admin），M6 管理后台加"同步"按钮 + 定时任务。
4. **限流多实例不共享**：内存实现，公网若多实例部署需 Redis。
5. **HTTPS**：nginx.conf 未配 HTTPS，生产建议前置云负载均衡或证书反代。
6. **BGE 模型首次下载**：容器启动时经 hf-mirror 下载（约 100MB），首次启动慢，之后缓存到 `/data` 卷。
