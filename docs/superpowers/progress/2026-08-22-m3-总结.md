## 🔀 关键决策与偏离

1. **向量存储绕开 pgvector**：开发环境无法访问 GitHub（pgvector 下载源），改为 PostgreSQL JSON 列存向量 + Python 端余弦相似度。注塑机知识库规模（几百~几千条）不需要 ANN 索引。已修订设计文档 §5.6。
2. **模型降级 BGE-M3 → bge-small-zh-v1.5**：BGE-M3 权重 2GB 下载过慢，降级到 bge-small-zh-v1.5（512 维，约 100MB）。小规模中文知识库语义检索足够，且 CPU 推理更快。模型经 hf-mirror 镜像下载，缓存目录设为项目内 `backend/data/hf_cache`（沙箱对 C 盘 .cache 无写权限）。
3. **torch 安装**：清华镜像对 torch 大文件 403，改用官方 CPU 源 `download.pytorch.org/whl/cpu`（torch 2.13.0+cpu）；sentence-transformers 用阿里云镜像。
4. **chunk_text 改为逐段分块**：简报的"贪心合并"逻辑与测试矛盾，按 TDD 以测试为契约改为逐段分块（超长段再切），对短条目语义检索更精确。
5. **发布时同步向量化**：审核通过（approve=True）时同步重建该知识 chunks（正文分块 + 问法别名）。同步化会拖慢发布接口（首次加载模型），后续可异步化。

## 📋 遗留项（后续改进）

1. **DEEPSEEK_API_KEY 未配置**：`backend/.env` 中仍为空，前端问答真实调用需先填 key。
2. **generate 无异常兜底**：DeepSeek 非 200/空响应无降级处理，建议 M4 补（结合工单兜底）。
3. **检索无关键词加权**：当前纯向量相似度，bge-small 语义检索已够用，关键词加权可作优化。
4. **NULL embedding 无防护**：chunk 均由 reindex 写入有效向量，暂无风险，可加防御。
5. **发布同步向量化拖慢接口**：可改异步（后台任务队列）。
6. **前端空 onMounted、IME 回车误触发**：轻微瑕疵。
7. 模型缓存 `backend/data/hf_cache` 约 100MB+，部署时需随部署包分发或首次启动预下载。
