## 🔀 关键决策与偏离

1. **编辑权限语义修正**：计划里 `_can_edit` 代码与测试自相矛盾，最终定案为**「engineer/admin 或作者本人可编辑」**（协作编辑）——符合设计文档 §6.5「engineer 可编辑知识」及团队共建场景。support 非作者编辑返回 403。
2. **知识单表 + kind 区分**：五类内容统一存 `knowledge_items`，`aliases`/`tags`/`case_fields` 用 JSON 列，符合设计 §5.2。
3. **附件类型仅凭扩展名判断**：未校验文件魔数（magic bytes），是简化实现，安全边界较弱，记录为后续加固项。
4. **附件存储为绝对路径**：`Attachment.storage_path` 存了绝对路径（本地开发方便），M5 部署（Docker）时需改为相对 `UPLOAD_DIR` 的路径，已记录。
5. **pydantic 弃用警告已消除**：Task 1 顺手把 `config.py` 的 `class Config` 改为 `model_config = {"env_file": ".env"}`。

## 🔌 接口变更清单（供 M3 及后续里程碑引用）

**后端（`/api` 前缀）**：
- `GET /api/knowledge`（列表，kind/category/status/q 过滤；support 只见 published，public 模式再过滤 publish_to_public）
- `GET /api/knowledge/{id}`（详情，support 看未发布 403）
- `POST /api/knowledge`（创建草稿）
- `PUT /api/knowledge/{id}`（更新，version+1）
- `POST /api/knowledge/{id}/submit`（draft→pending，作者）
- `POST /api/knowledge/{id}/review`（pending→published/退回，engineer/admin，body: approve/comment）
- `POST /api/knowledge/{id}/archive`（→archived，engineer/admin）
- `POST /api/knowledge/{id}/publish-toggle`（切换 publish_to_public，engineer/admin）
- `POST /api/files?knowledge_id=...`（附件上传）、`GET /api/files/{id}/download`（下载）

**后端模块**：
- `app.models.knowledge`：`KnowledgeItem`/`Attachment`/`KINDS`/`STATUSES`

- `app.routers.knowledge`（CRUD+流转）、`app.routers.files`（附件）

**前端（Vue3）**：
- `views/knowledge/KnowledgeList.vue`（内网管理列表）、`KnowledgeEdit.vue`（编辑器）、`ReviewCenter.vue`（审核）、`KnowledgeBrowse.vue`（浏览）、`KnowledgeDetail.vue`（详情）

## 📋 遗留项（Minor / 后续改进）

1. **详情页未展示附件**：Task 8 详情页只渲染 markdown 正文，未展示上传的图片/视频/PDF。设计 §4.3 要求「正文（代码块、表格、图片）、视频播放」——属功能缺口，建议 M3 问答引擎一并补（后端 `GET /knowledge/{id}` 需返回附件列表 + 前端展示）。
2. **新建知识时无法直接上传附件**：附件上传依赖 `form.id`（先保存拿到 id 再上传）。UX 限制，可后续改为「新建先存草稿再传」。
3. **markdown 预览无排版样式**：`markdown-body` 未引入 github-markdown-css，正文用浏览器默认样式。后续加样式库。
4. **附件类型仅凭扩展名**、**上传先读整个文件进内存**（大文件内存放大）、**storage_path 存绝对路径**（M5 改相对）。
5. 前端多处无 try/catch（依赖全局拦截器提示）；表格按钮在部分状态可能拥挤换行。
6. `Query` 在 knowledge.py 中导入未使用（lint 噪声）。
